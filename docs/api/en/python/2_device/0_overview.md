# Device

`cqlib.device`

`cqlib.device` describes the static information of a quantum device and the state of task execution: the topology formed by qubits and couplings, the calibration properties of qubits and edges, the layout from logical qubits to physical qubits, noise models, and execution results and status.

## Overview

The device module splits hardware-related data into several mutually independent groups of objects: the topology describes only connectivity, properties describe only calibration data, the layout describes only the mapping, and the noise model describes only channels. Compilation and execution each take what they need, with no coupling between them.

### Topology

`Topology` consists of a set of physical qubits and a list of couplings. Couplings are directed: a coupling on `(control, target)` does not imply one in the reverse direction, so connectivity queries fall into two categories, `successors` / `predecessors` (directed) and `neighbors_undirected` (undirected), and degree queries likewise fall into `out_degree` / `in_degree`. A coupling may carry a name label, used for identification only.

### Device and properties

`Device` layers device-level defaults and local overrides on top of a topology, and records the device name, registered qubits, invalid qubits, native gate set and calibration time. Qubit-level properties are described by `QubitProp` (`t1`, `t2`, `frequency`, readout error and readout confusion probabilities), and edge-level properties by `EdgeProp`; both hold a group of `InstructionProp` (an instruction, an error rate and an optional duration).

When querying the properties of a qubit, local values take precedence, and an unset value falls back to the device-level default: `device.get_t1(0)` takes the local value, and `device.get_t1(2)` takes `default_t1`. The device also provides static constructors such as `line`, `ring`, `star` and `grid`, which directly generate a topology and qubit set in common shapes.

### Native instruction capability

Device-level `native_gates` is the global default capability; if a qubit or a directed edge configures its own instruction list through `add_native_instruction`, that list is a complete override of the capability at that place and does not write back to the default. Calibration data only attaches an error rate and a duration to supported instructions; it never turns an unsupported instruction into a supported one. `validate_operation` / `validate_circuit` use the same set of rules to validate whether a circuit can run on the device.

### Layout

`Layout` maintains the mapping from logical qubits to physical qubits; a physical qubit that carries no logical qubit is a vacant physical qubit. The mapping can be read as a whole through `l2p_map` / `p2l_map`, or queried per qubit; `swap_physical` swaps the logical qubits carried at two physical positions, which is the basic operation for moving logical qubits during routing.

### Noise model

`NoiseModel` registers noise channels by qubit and operation: readout error is represented by `ReadoutError`, single-qubit channels are generated by the static methods of `SingleQubitNoise` (bit flip, phase flip, Pauli, depolarizing, amplitude damping, phase damping), and two-qubit channels are generated by `TwoQubitNoise` (depolarizing, independent channel composition, correlated Pauli). A channel can be converted into Kraus operators with `to_kraus`, for use in density matrix simulation. Queries use `OperationKey` to specify the gate and qubit combination.

```python
from cqlib.circuit import StandardGate
from cqlib.device import NoiseModel, ReadoutError, TwoQubitNoise

model = NoiseModel()
model.add_readout_error(0, ReadoutError(0.1, 0.2))
model.add_two_qubit_error(StandardGate.CX, 0, 1, TwoQubitNoise.depolarizing(0.02))
```

### Execution result

`ExecutionResult` records the lifecycle of one task: it is in `Status.queued()` after creation, enters the running state after `start`, and ends the task with `finish` / `fail` / `cancel`. Measurement results are represented by `Outcome`, which compresses the bitstring into 64-bit chunks and supports both reading a bit by position and restoring the bitstring; `counts` and `probabilities` are the measurement counts and the normalized probabilities of each result respectively.

## Common entry points

```python
from cqlib import Qubit
from cqlib.circuit import Instruction, StandardGate
from cqlib.device import Device, QubitProp, Topology

topo = Topology([0, 1, 2], [(0, 1, "G1"), (1, 2, "G2")])
device = Device("mock_backend", [Qubit(0), Qubit(1), Qubit(2)], topo)
device.default_t1 = 50.0
device.native_gates = [Instruction.from_standard_gate(StandardGate.X)]

qp0 = QubitProp(0.02)
qp0.t1 = 80.0
device.add_qubit_properties(0, qp0)

assert device.get_t1(0) == 80.0  # 局部属性
assert device.get_t1(2) == 50.0  # 回退到设备级默认值
```

## Core concepts and terms

| Term | Description |
| --- | --- |
| **Physical qubit** | A physical position on the device, represented by `PhysicalQubit`. |
| **Logical qubit** | A wire in a circuit, represented by `LogicalQubit`; even with the same index, it is distinct from a physical qubit. |
| **Topology** | The graph formed by physical qubits and the couplings between them, represented by `Topology`. |
| **Coupling** | A connection between two physical qubits over which a two-qubit gate can be executed. |
| **Directed coupling** | A coupling with a direction: the existence of a coupling on `(control, target)` does not imply one in the reverse direction. |
| **Native instruction** | An instruction that can be executed directly on the device; the device-level set is the default capability, and qubits and edges can each override it. |
| **Local override** | A qubit's or an edge's native instruction list; once non-empty, it completely replaces the device-level default capability and does not write back to the default. |
| **Default fallback** | When querying the properties of a qubit, a qubit without a local value returns the device-level default. |
| **Initial layout** | The initial mapping from logical qubits to physical qubits, represented by `Layout`. |
| **Vacant physical qubit** | A physical qubit that currently carries no logical qubit. |
| **Noise channel** | A set of operators describing one kind of noise effect, convertible into Kraus operators with `to_kraus`. |
| **Readout error** | The probability of reading `\|0>` as 1 or reading `\|1>` as 0 during measurement. |
| **Measurement result** | The bitstring obtained from one sample, represented by `Outcome`. |

## `cqlib.device` API overview

### Topology

| Name | Description |
| --- | --- |
| [`Topology`](1_topology.md) | The directed graph formed by physical qubits and a coupling list, with add/remove and connectivity queries. |
| [`Topology.line`](1_topology.md) | Static method that constructs a topology in a straight-line shape. |

### Device and properties

| Name | Description |
| --- | --- |
| [`Device`](2_properties_device.md) | The device object: topology, qubit set, native gate set, calibration time and default properties. |
| [`Device.line`](2_properties_device.md) / [`Device.ring`](2_properties_device.md) / [`Device.star`](2_properties_device.md) / [`Device.grid`](2_properties_device.md) | Static methods that build a device in common shapes. |
| [`QubitProp`](2_properties_device.md) | Qubit properties: readout error, confusion probabilities, `t1` / `t2`, frequency and native instruction properties. |
| [`EdgeProp`](2_properties_device.md) | Edge properties: the native instruction properties on that directed edge. |
| [`InstructionProp`](2_properties_device.md) | Instruction properties: the instruction object, the error rate and an optional duration. |
| [`Device.validate_circuit`](2_properties_device.md) / [`Device.validate_operation`](2_properties_device.md) | Validate a circuit or a single operation against the native capability and the topology. |

### Layout

| Name | Description |
| --- | --- |
| [`Layout`](3_layout.md) | The mapping from logical qubits to physical qubits, with bind, unbind and physical qubit swap. |
| [`Layout.from_pairs`](3_layout.md) | Construct a layout from `(logical id, physical id)` pairs and the total number of physical qubits. |
| [`LogicalQubit`](3_layout.md) / [`PhysicalQubit`](3_layout.md) | The types for logical and physical qubits, whose string forms are `L0` and `P11` respectively. |

### Noise model

| Name | Description |
| --- | --- |
| [`NoiseModel`](4_noise.md) | A container registering noise channels by qubit and operation. |
| [`SingleQubitNoise`](4_noise.md) | Single-qubit noise channels, including bit flip, phase flip, Pauli, depolarizing and two kinds of damping. |
| [`TwoQubitNoise`](4_noise.md) | Two-qubit noise channels, including depolarizing, independent composition and correlated Pauli. |
| [`ReadoutError`](4_noise.md) | Readout error, recording `P(0\|1)` and `P(1\|0)` separately. |
| [`OperationKey`](4_noise.md) | The key for noise queries, formed by combining a gate and qubit indices. |

### Execution result

| Name | Description |
| --- | --- |
| [`ExecutionResult`](5_result.md) | The result of task execution, with counts, probabilities and timestamps. |
| [`Status`](5_result.md) | Task status: queued, running, completed, failed and cancelled. |
| [`Outcome`](5_result.md) | A compact measurement result bitstring, supporting bitwise access and restoration. |

## Quick examples

### 1. Build a device and configure properties

```python
from cqlib import Qubit
from cqlib.circuit import Instruction, StandardGate
from cqlib.device import Device, EdgeProp, InstructionProp, QubitProp, Topology

topo = Topology([0, 1, 2], [(0, 1, "G1"), (1, 2, "G2")])
device = Device("mock_backend", [Qubit(0), Qubit(1), Qubit(2)], topo)
device.default_t1 = 50.0
device.default_t2 = 35.0
device.default_readout_error = 0.05
device.native_gates = [
    Instruction.from_standard_gate(StandardGate.X),
    Instruction.from_standard_gate(StandardGate.CX),
]

qp0 = QubitProp(0.02)
qp0.t1 = 80.0
qp0.t2 = 70.0
device.add_qubit_properties(0, qp0)

ep01 = EdgeProp()
cx_inst = Instruction.from_standard_gate(StandardGate.CX)
ep01.add_native_instruction(InstructionProp(cx_inst, 0.06))
device.add_edge_properties(0, 1, ep01)
```

Writing a nonexistent qubit or edge is rejected:

```python
import pytest

with pytest.raises(ValueError):
    device.add_qubit_properties(9, QubitProp(0.01))

with pytest.raises(ValueError):
    device.add_edge_properties(0, 9, EdgeProp())
```

### 2. Build a layout and swap physical qubits

```python
from cqlib import Qubit
from cqlib.device import Layout, PhysicalQubit

layout = Layout(
    logical=[0, 1], physical=[10, 11, 12], init_map={Qubit(0): Qubit(11)}
)
assert layout.num_logical == 2
assert layout.num_physical == 3
assert layout.num_vacant_physical == 1
assert layout.get_physical(0) == PhysicalQubit(11)

on_11 = layout.get_logical(11)
on_12 = layout.get_logical(12)

layout.swap_physical(11, 12)
assert layout.get_logical(11) == on_12
assert layout.get_logical(12) == on_11
```

The mapping tables can be read as a whole:

```python
from cqlib import Qubit
from cqlib.device import Layout, LogicalQubit, PhysicalQubit

layout = Layout(logical=[0], physical=[10, 11], init_map={Qubit(0): Qubit(11)})
assert layout.l2p_map == {LogicalQubit(0): PhysicalQubit(11)}
assert layout.p2l_map == {PhysicalQubit(11): LogicalQubit(0)}
```

### 3. Record an execution result

```python
from cqlib import Qubit
from cqlib.device import ExecutionResult

result = ExecutionResult(
    task_id="task-1",
    qubits=[Qubit(0), Qubit(1)],
    shots=100,
    num_qubits=2,
    backend="sim",
)
assert result.status.kind == "queued"

result.start()
assert result.status.kind == "running"

result.finish({"00": 60, "11": 40})
assert result.status.kind == "completed"
assert result.counts["00"] == 60

result.calc_probabilities()
assert result.probabilities["00"] == 0.6
```

## Validation and error handling

Failures in the device binding layer uniformly raise `ValueError`, with no custom exception types; exception messages come directly from the underlying error description.

| Exception | When it occurs |
| --- | --- |
| `ValueError` | The qubit or edge is not in the device/topology, for example adding properties to a nonexistent qubit or adding edge properties in a nonexistent direction. |
| `ValueError` | Construction or modification conflicts of the topology and the layout: duplicate qubits, duplicate couplings, self-coupling, duplicate or already bound logical qubits, an already occupied physical qubit, and so on. |
| `ValueError` | Invalid probability-like parameters: an error rate, readout error or noise channel parameter outside `[0, 1]` or not a finite value; the sum of the three probabilities of a Pauli channel exceeds 1. |
| `ValueError` | Invalid time-like parameters: `t1` / `t2` / `frequency` must be finite positive numbers. |
| `ValueError` | Invalid native instructions: device-level native gates accept only standard gates of at most two qubits, while the qubit level and the edge level accept only one-qubit and two-qubit standard gates respectively; when rejected, the device keeps its previous capability. |
| `ValueError` | `validate_operation` / `validate_circuit` validation failure: the qubit is unusable, a directed coupling is missing, the instruction is not in the native gate set, or the instruction has not been decomposed yet. |
| `ValueError` | Invalid measurement data: the bitstring of an `Outcome` contains a character other than `0` / `1`; a key of `finish` or `from_counts` has a length not equal to `num_qubits`, or different keys fold to the same result. |
| `ValueError` | The time passed to `set_calibration_time` is outside the representable range. |
| `TypeError` / `OverflowError` | The parameter type or value domain does not match, for example a qubit index passed as a non-integer or a negative number. |

Probability-like parameters are validated at write time, so an invalid value never lands on a device or noise model object.
