# UnitaryGate

- `cqlib_core::circuit::UnitaryGate`
- `cqlib_core::circuit::gate::unitary_gate::UnitaryMatrix`

```rust
use cqlib_core::circuit::UnitaryGate;
```

`UnitaryGate` is used in the Rust core to define user-defined unitary gates outside the standard gate set. It suits gates that have clear unitary matrix semantics but do not belong to the `StandardGate` enum, for example a custom oracle, a hardware calibration gate, a black-box unitary matrix generated by an external tool, or a parameterized custom gate whose symbolic matrix definition needs to be retained.

---

## Constructor

```rust
pub fn new(label: &str, num_qubits: u16, num_params: u16) -> Self
```

`UnitaryGate::new(label, num_qubits, num_params)` creates a custom unitary gate object to which no concrete definition has been attached yet.

| Parameter | Description |
| --- | --- |
| `label` | The readable name of the gate, usually used for debugging, visualization and IR output. |
| `num_qubits` | The number of qubits the gate acts on. |
| `num_params` | The number of positional parameters to pass in each time the gate is applied. |

```rust
use cqlib_core::circuit::UnitaryGate;

let gate = UnitaryGate::new("Oracle", 2, 0);

assert_eq!(gate.label(), "Oracle");
assert_eq!(gate.num_qubits(), 2);
assert_eq!(gate.num_params(), 0);
```

Note that every call to `UnitaryGate::new()` generates a new UUID.

---

## Attributes and query interfaces

`UnitaryGate` provides a set of query methods for reading the gate metadata and the definition already attached.

| Method | Returns | Description |
| --- | --- | --- |
| `label()` | `&str` | Return the readable name of the gate. |
| `num_qubits()` | `u16` | Return the number of qubits the gate acts on. |
| `num_params()` | `u16` | Return the number of positional parameters required each time the gate is applied. |
| `matrix()` | `Option<&Array2<Complex<f64>>>` | Return the numeric matrix definition; if no numeric matrix definition was used, return `None`. |
| `symbolic_matrix()` | `Option<&SymbolicMatrix>` | Return the symbolic matrix definition. |
| `matrix_params()` | `Option<&[String]>` | Return the order of the symbolic matrix parameter names. |
| `matrix_repr()` | `Option<&UnitaryMatrix>` | Return the raw matrix representation. |
| `circuit()` | `&Option<Arc<FrozenCircuit>>` | Return the circuit-backed definition. |

## `UnitaryMatrix`

`UnitaryMatrix` is the raw matrix representation enum of `UnitaryGate`, readable through `matrix_repr()`.

```rust
pub enum UnitaryMatrix {
    Numeric(Array2<Complex<f64>>),
    Symbolic(SymbolicMatrix),
}
```

| Variant | Description |
| --- | --- |
| `Numeric(Array2<Complex<f64>>)` | A numeric matrix, applicable only to a non-parameterized unitary gate definition. |
| `Symbolic(SymbolicMatrix)` | A symbolic matrix whose free symbols are mapped positionally in the order of the gate's `matrix_params`. |

---

## Numeric matrix definition

```rust
pub fn with_matrix(self, mat: Array2<Complex<f64>>) -> Result<Self, CircuitError>
```

`with_matrix()` attaches a fixed numeric matrix definition to a custom gate. The matrix must be a complex square matrix with the shape:

```text
2^num_qubits × 2^num_qubits
```

In addition, when a numeric matrix definition is used, `num_params` must be `0`, because the matrix of the gate is already fully determined and no extra positional parameter needs to be passed in when the gate is applied. Matrix elements must be finite values, and the matrix must be unitary, that is, `U†U` is the identity matrix within tolerance; otherwise an error is returned.

```rust
use cqlib_core::circuit::UnitaryGate;
use ndarray::array;
use num_complex::Complex64;

let x = array![
    [Complex64::new(0.0, 0.0), Complex64::new(1.0, 0.0)],
    [Complex64::new(1.0, 0.0), Complex64::new(0.0, 0.0)],
];

let gate = UnitaryGate::new("CustomX", 1, 0).with_matrix(x)?;

assert!(gate.matrix().is_some());

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

## Symbolic matrix definition

```rust
pub fn with_symbolic_matrix<I, S>(
    self,
    params: I,
    matrix: SymbolicMatrix,
) -> Result<Self, CircuitError>
where
    I: IntoIterator<Item = S>,
    S: Into<String>,
```

`with_symbolic_matrix()` attaches a symbolic matrix definition to a custom gate. Elements of the symbolic matrix may contain `Parameter` expressions, which suits parameterized custom unitary gates.

Here, `params` specifies how the positional parameters passed in when the gate is applied are mapped to the variable names in the symbolic matrix. That is, `params` is not merely a descriptive list; it defines the parameter binding order. When `matrix_for_params()` is called, or the gate is appended to a circuit, the `i`-th parameter passed in is bound to the symbol name at `params[i]`. The length of `params` must equal `num_params`, and every free symbol appearing in the symbolic matrix must already be declared in `params`.

```rust
use cqlib_core::circuit::{Parameter, UnitaryGate};
use cqlib_core::circuit::symbolic_matrix::{SymbolicComplex, SymbolicMatrix};

let theta = Parameter::symbol("theta");

let matrix = SymbolicMatrix::from_shape_vec(
    (2, 2),
    vec![
        SymbolicComplex::one(),
        SymbolicComplex::zero(),
        SymbolicComplex::zero(),
        SymbolicComplex::exp_i(theta),
    ],
).expect("valid 2x2 symbolic matrix");

let gate = UnitaryGate::new("PhaseLike", 1, 1)
    .with_symbolic_matrix(["theta"], matrix)?;

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

In the example above, the symbolic matrix contains the variable `theta`, and `with_symbolic_matrix(["theta"], matrix)` declares that the gate has exactly one positional parameter when it is applied, and that this parameter is bound to `theta` in the matrix.

## Circuit-backed definition

```rust
pub fn with_circuit(self, circuit: Arc<FrozenCircuit>) -> Result<Self, CircuitError>
```

`with_circuit()` uses a `FrozenCircuit` as the definition of a `UnitaryGate`. When the behavior of a gate can be described by a sub-circuit, this form can be used to retain the inner circuit structure. When the matrix is requested, Cqlib binds the inner circuit according to the parameters passed in when the gate is applied, and calls `circuit_to_matrix()` to compute the matrix.

```rust
use cqlib_core::circuit::{Circuit, Qubit, UnitaryGate};
use cqlib_core::circuit::gate::FrozenCircuit;
use std::sync::Arc;

let mut inner = Circuit::new(2);
inner.h(Qubit::new(0))?;
inner.cx(Qubit::new(0), Qubit::new(1))?;

let gate = UnitaryGate::new("BellPrep", 2, 0)
    .with_circuit(Arc::new(FrozenCircuit::new(inner)))?;

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

## Computing a concrete matrix

```rust
pub fn matrix_for_params(
    &self,
    params: &[f64],
) -> Result<Cow<'_, Array2<Complex<f64>>>, CircuitError>
```

`matrix_for_params(params)` obtains the concrete numeric matrix of a `UnitaryGate` once the positional parameters are given. The method dispatches automatically according to the definition form of the gate:

| Definition form | Matrix computation method |
| --- | --- |
| Numeric matrix | Return the saved matrix directly, usually in borrowed form. |
| Symbolic matrix | Bind `params` to the symbol names in the order given by `matrix_params()`, then evaluate the `SymbolicMatrix`. |
| Circuit-backed definition | Bind parameters in the order of the inner circuit's `used_symbols()`, then call `circuit_to_matrix()` on the inner circuit. |

## Appending to `Circuit`

A `UnitaryGate` can be added to a circuit through the custom unitary gate appending interfaces provided by `Circuit`.

```rust
circuit.unitary(gate, qubits)?;
circuit.unitary_with_params(gate, qubits, params)?;
```

- `unitary(gate, qubits)` applies to a custom gate without positional parameters;
- `unitary_with_params(gate, qubits, params)` applies to a custom gate with positional parameters.

```rust
use cqlib_core::circuit::{Circuit, Qubit, UnitaryGate};
use ndarray::array;
use num_complex::Complex64;

let x = array![
    [Complex64::new(0.0, 0.0), Complex64::new(1.0, 0.0)],
    [Complex64::new(1.0, 0.0), Complex64::new(0.0, 0.0)],
];

let gate = UnitaryGate::new("CustomX", 1, 0).with_matrix(x)?;

let mut circuit = Circuit::new(1);
circuit.unitary(gate, vec![Qubit::new(0)])?;

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

## Comparison of definition forms

| Definition form | Parameter support | Preserves circuit structure | Matrix source | Typical use |
| --- | --- | --- | --- | --- |
| `with_matrix()` | Does not support application parameters, `num_params` must be 0 | No | Save `Array2<Complex64>` directly | Fixed black-box matrices, hardware calibration gates, test oracles. |
| `with_symbolic_matrix()` | Supports `num_params` positional parameters | No | Evaluate the `SymbolicMatrix` | Parameterized custom matrix gates, symbolic phase gates. |
| `with_circuit()` | Supports symbol binding of the inner circuit | Yes | Bind parameters to the inner circuit and then call `circuit_to_matrix()` | Carry a circuit definition in the form of a custom unitary gate. |

---

## Differences from `StandardGate` and `CircuitGate`

| Type | Suitable scenarios | Characteristics |
| --- | --- | --- |
| `StandardGate` | Standard gates natively supported by Cqlib | Lightweight, optimizable and with clear gate semantics, suitable as a compilation basis. |
| `CircuitGate` | Wrapping a sub-circuit as a reusable composite gate | Preserves module boundaries, which facilitates decomposition and structural analysis. |
| `UnitaryGate` | Custom unitary gates outside the standard gate set | Can be defined by a matrix, a symbolic matrix or a frozen circuit, suitable for black-box or special unitary gates. |
