`cqlib_core::circuit::ansatz`

```rust
use cqlib_core::circuit::ansatz::{

    TwoLocal,
    BasicEntanglerLayers,

    real_amplitudes,

    zz_feature_map,
    pauli_feature_map,
};
```

The `ansatz` module provides a set of reusable parameterized quantum circuit templates, mainly for scenarios such as variational quantum algorithms, quantum machine learning, combinatorial optimization and Hamiltonian time evolution. With these templates, a `Circuit` with a clear structure and consistent parameter naming can be generated from a small amount of configuration, avoiding repeated hand-written construction of common circuit structures in algorithm development.

---

## `Ansatz` trait

The `Ansatz` trait defines the unified interface of ansatz templates. Templates implementing this trait all support configuration validation, circuit construction, parameter count query and qubit count query.

```rust
pub trait Ansatz {
    fn validate(&self) -> Result<(), CircuitError> { ... }
    fn build_circuit(&self, prefix: &str) -> Result<Circuit, CircuitError>;
    fn num_parameters(&self) -> usize;
    fn num_qubits(&self) -> usize;
}
```

| Method | Returns | Description |
| --- | --- | --- |
| `validate()` | `Result<(), CircuitError>` | Check whether the template configuration is valid, for example whether the qubit count, gate arity, topology and Hamiltonian meet the requirements. |
| `build_circuit(prefix)` | `Result<Circuit, CircuitError>` | Generate a parameterized circuit from the current template configuration. |
| `num_parameters()` | `usize` | Return the number of independent parameters required by the circuit generated by this template. |
| `num_qubits()` | `usize` | Return the number of qubits this template acts on. |

```rust
use cqlib_core::circuit::ansatz::{Ansatz, TwoLocal};

let ansatz = TwoLocal::new(3).reps(2);

ansatz.validate()?;

let circuit = ansatz.build_circuit("theta")?;

assert_eq!(ansatz.num_qubits(), 3);
assert_eq!(circuit.symbols().len(), ansatz.num_parameters());

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

## Builder style and parameter prefix

Templates in the `ansatz` module are usually configured in builder style. Configuration methods return the configured template object, so that the number of repetition layers, rotation gates, entanglement gates, entanglement topology or evolution strategy can be specified step by step through chained calls.

```rust
use cqlib_core::circuit::StandardGate;
use cqlib_core::circuit::ansatz::{Ansatz, EntanglementTopology, TwoLocal};

let ansatz = TwoLocal::new(4)
    .reps(2)
    .rotation_gates(vec![StandardGate::RY, StandardGate::RZ])
    .entanglement_gate(StandardGate::CX)
    .entanglement(EntanglementTopology::Linear);

let circuit = ansatz.build_circuit("theta")?;

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

The `prefix` in `build_circuit(prefix)` is used to generate symbolic parameter names in the circuit. For example, common templates generate parameter names such as `{prefix}_0` and `{prefix}_1`; the QAOA template generates parameter names with `gamma` / `beta` semantics; Hamiltonian evolution templates usually use a time parameter name.

When combining multiple ansatz templates in the same model, use a different prefix for each module to avoid symbol name conflicts. For example:

```text
encoder_0, encoder_1, ...
ansatz_0, ansatz_1, ...
qaoa_gamma_0, qaoa_beta_0, ...
```

## `EntanglementTopology`

```rust
pub enum EntanglementTopology {
    Linear,
    Circular,
    Full,
    Custom(Vec<(usize, usize)>),
}
```

`EntanglementTopology` describes the entanglement connectivity in multi-qubit templates. It determines between which qubits a two-qubit gate or a many-body Pauli evolution term is added in each layer.

| Topology | Description |
| --- | --- |
| `Linear` | Nearest-neighbor chain connectivity, for example `(0, 1), (1, 2), ...`. |
| `Circular` | Adds a connection between the first and last qubits on top of `Linear`. |
| `Full` | Fully connected topology, where any two qubits can be connected. |
| `Custom(Vec<(usize, usize)>)` | Connection pairs explicitly specified by the user. |

The common methods are as follows:

| Method | Description |
| --- | --- |
| `generate_pairs(num_qubits)` | Generate two-qubit connection pairs from the topology. |
| `generate_k_tuples(k, num_qubits)` | Generate k-local groups of acted-on qubits from the topology. |

```rust
use cqlib_core::circuit::ansatz::EntanglementTopology;

let topology = EntanglementTopology::Linear;
let pairs = topology.generate_pairs(4);

assert_eq!(pairs, vec![(0, 1), (1, 2), (2, 3)]);
```

## `TwoLocal`

`TwoLocal` is a common hardware-friendly ansatz. It consists of alternating single-qubit rotation layers and multi-qubit entanglement layers, and suits VQE, quantum machine learning and general variational circuit construction.

```rust
use cqlib_core::circuit::StandardGate;
use cqlib_core::circuit::ansatz::{Ansatz, EntanglementTopology, TwoLocal};

let ansatz = TwoLocal::new(3)
    .reps(2)
    .rotation_gates(vec![StandardGate::RY, StandardGate::RZ])
    .entanglement_gate(StandardGate::CX)
    .entanglement(EntanglementTopology::Linear);

let circuit = ansatz.build_circuit("theta")?;

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

The configuration methods are as follows:

| Method | Description |
| --- | --- |
| `reps(reps)` | Set the number of repetition layers. |
| `rotation_gates(gates)` | Set the single-qubit parameterized rotation gates used in each layer. |
| `entanglement_gate(gate)` | Set the two-qubit gate used in the entanglement layer. |
| `entanglement(topology)` | Set the entanglement topology. |
| `skip_final_rotation_layer(skip)` | Set whether to skip the final rotation layer. |

When using `TwoLocal`, ensure that the rotation gates are single-qubit parameterized gates and that the entanglement gate is a suitable multi-qubit gate. If a gate arity does not match the template requirements, `validate()` or `build_circuit()` returns an error.

## Feature Maps

A feature map maps classical data into quantum circuit parameters, and is a common component in quantum machine learning and quantum kernel methods.

| Type | Description |
| --- | --- |
| `AngleEncoding` | Map each input feature to a single-qubit rotation angle. |
| `BasisEncoding` | Prepare a computational basis state according to a bitstring, without introducing continuous parameters. |
| `ZFeatureMap` | First-order Pauli-Z feature map. |
| `IQPFeatureMap` | IQP-style diagonal feature map. |
| `ZZFeatureMap` | Second-order ZZ feature map, commonly used in quantum kernel methods. |
| `PauliFeatureMap` | Feature map supporting arbitrary Pauli string templates. |

```rust
use cqlib_core::circuit::ansatz::{Ansatz, EntanglementTopology, ZZFeatureMap};

let fm = ZZFeatureMap::new(3)
    .reps(2)
    .entanglement(EntanglementTopology::Full);

let circuit = fm.build_circuit("x")?;

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

## Convenience constructors

For the most frequently used templates, the `ansatz` module provides a set of convenience constructors that create instances directly by template name. They still return the template objects listed above, and configuration can be adjusted further with builder methods.

| Function | Returns | Description |
| --- | --- | --- |
| `real_amplitudes(num_qubits, reps, entanglement)` | `TwoLocal` | A template consisting of alternating `RY` rotation layers and entanglement layers. |
| `efficient_su2(num_qubits, reps, entanglement)` | `TwoLocal` | A template consisting of alternating `RY` and `RZ` rotation layers and entanglement layers. |
| `zz_feature_map(num_qubits, reps, entanglement)` | `ZZFeatureMap` | Second-order ZZ feature map. |
| `pauli_feature_map(num_qubits, reps, paulis, entanglement)` | `PauliFeatureMap` | A feature map constructed from the given Pauli string templates. |

Here `paulis` is a list of `(PauliString, String)`, where the former specifies the interaction type and the latter is the label of that Pauli term.

```rust
use cqlib_core::circuit::ansatz::{
    efficient_su2,
    real_amplitudes,
    zz_feature_map,
    Ansatz,
    EntanglementTopology,
};

let ansatz = real_amplitudes(3, 2, EntanglementTopology::Linear);

assert_eq!(ansatz.num_qubits(), 3);
assert_eq!(ansatz.num_parameters(), 9);

let su2 = efficient_su2(2, 1, EntanglementTopology::Full);

assert_eq!(su2.num_parameters(), 8);

let fm = zz_feature_map(3, 1, EntanglementTopology::Full);

assert_eq!(fm.num_parameters(), 3);
```

## Layer templates

Besides the general `TwoLocal`, the `ansatz` module also provides common layer templates for quickly constructing highly regular trainable circuits.

### 1. `BasicEntanglerLayers`

`BasicEntanglerLayers` usually consists of single-qubit rotation layers and entanglement layers with a fixed pattern, and suits training circuits with a simple structure and a controllable parameter count.

```rust
use cqlib_core::circuit::StandardGate;
use cqlib_core::circuit::ansatz::{Ansatz, BasicEntanglerLayers};

let ansatz = BasicEntanglerLayers::new(4)
    .reps(3)
    .rotation_gate(StandardGate::RY)
    .entanglement_gate(StandardGate::CX);

let circuit = ansatz.build_circuit("w")?;

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

### 2. `StronglyEntanglingLayers`

`StronglyEntanglingLayers` usually uses stronger single-qubit rotations and a ranged entanglement pattern, and suits variational models that require stronger expressivity.

```rust
use cqlib_core::circuit::StandardGate;
use cqlib_core::circuit::ansatz::{Ansatz, StronglyEntanglingLayers};

let ansatz = StronglyEntanglingLayers::new(4)
    .reps(3)
    .entanglement_gate(StandardGate::CX)
    .ranges(vec![1, 2]);

let circuit = ansatz.build_circuit("w")?;

# Ok::<(), cqlib_core::circuit::CircuitError>(())
```

## `QAOAAnsatz`

`QAOAAnsatz` constructs the parameterized circuit of the Quantum Approximate Optimization Algorithm (QAOA). In circuit structure, QAOA alternately applies the time evolution of the cost Hamiltonian and the mixer Hamiltonian.

The typical form can be understood as:

```text
U(β, γ) = ∏_l exp(-i β_l H_M) exp(-i γ_l H_C)
```

Where:

- `H_C` is the problem Hamiltonian, also called the cost operator;
- `H_M` is the mixer Hamiltonian, usually an X mixer by default;
- `p = reps` is the number of QAOA layers;
- Each layer usually contains one `γ_l` and one `β_l` parameter, so `num_parameters()` is usually `2 * reps`.

The configuration methods are as follows:

| Method | Description |
| --- | --- |
| `new(cost_operator)` | Create a QAOA ansatz from the cost Hamiltonian. |
| `reps(reps)` | Set the number of QAOA layers `p`. |
| `mixer(mixer_operator)` | Set a custom mixer Hamiltonian. |
| `initial_state(circuit)` | Set the initial state circuit. |
| `evolution_strategy(strategy)` | Set the Hamiltonian evolution strategy. |

When using QAOA, ensure that the cost Hamiltonian, the mixer Hamiltonian and the initial state circuit have the same number of qubits. If the dimensions do not match, an error is returned when the circuit is built.

## Hamiltonian Evolution

Hamiltonian evolution templates construct parameterized time evolution circuits of the form `exp(-i H t)`. Such templates are commonly used to simulate the evolution of quantum systems, to build QAOA sub-modules, or to validate the gate-level decomposition of a Pauli Hamiltonian.

### 1. `EvolutionStrategy`

`EvolutionStrategy` specifies how a Hamiltonian evolution is converted into a sequence of quantum gates.

| Variant | Description |
| --- | --- |
| `Exact` | Use exact Pauli rotation decomposition for a pairwise commuting Hamiltonian; if the terms do not commute, an error is returned at build time. |
| `Auto { steps }` | Choose the strategy automatically: use exact when the terms commute, and first-order Trotter with `steps` steps when they do not. |
| `Trotter { mode, steps }` | Explicitly use the given Trotter-Suzuki decomposition mode and number of steps. |

### 2. `EvolutionInfo`

`EvolutionInfo` describes the evolution strategy actually used and Hamiltonian structure information, and is usually returned by `PauliEvolutionAnsatz::evolution_info()`.

Common fields include:

- `is_exact`
- `steps`
- `trotter_mode`
- `all_terms_commute`
- `num_terms`

This information can be used to debug the evolution decomposition, record experiment configurations, or state in a report whether an evolution circuit is an exact decomposition.

### 3. `PauliEvolutionAnsatz`

`PauliEvolutionAnsatz` constructs the time evolution circuit of a Pauli Hamiltonian. The circuit generated by this template usually contains only one time parameter. The default parameter name may be `{prefix}_t`, and it can also be specified through `with_time_param_name()`, for example `tau`.
