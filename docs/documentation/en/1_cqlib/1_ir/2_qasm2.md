# OpenQASM 2.0 support

OpenQASM 2.0 is a very widely used circuit exchange format in the quantum computing ecosystem. It is suitable for describing static circuits dominated by quantum gates, registers, measurements and simple classical conditions, and it is also the format supported by default in many public benchmarks and old toolchains.

Corresponding Python module:

```python
from cqlib.ir import qasm2
```

## 1. API overview

| Function | Use | Example |
|---|---|---|
| `qasm2.loads(text)` | Parse a `Circuit` from an OpenQASM 2.0 string | `circuit = qasm2.loads(qasm_text)` |
| `qasm2.load(path)` | Parse a `Circuit` from an OpenQASM 2.0 file | `circuit = qasm2.load("input.qasm")` |
| `qasm2.dumps(circuit)` | Export a `Circuit` as an OpenQASM 2.0 string | `text = qasm2.dumps(circuit)` |
| `qasm2.dump(circuit, path)` | Write a `Circuit` to an OpenQASM 2.0 file | `qasm2.dump(circuit, "output.qasm")` |

## 2. Minimal OpenQASM 2.0 program

```text
OPENQASM 2.0;
include "qelib1.inc";
qreg q[2];
h q[0];
cx q[0],q[1];
```

Loading in Cqlib:

```python
from cqlib.ir import qasm2

qasm_code = """
OPENQASM 2.0;
include "qelib1.inc";
qreg q[2];
h q[0];
cx q[0],q[1];
"""

circuit = qasm2.loads(qasm_code)
print(circuit.num_qubits)
print(len(circuit.operations))
```

## 3. Handling of `qelib1.inc`

A common OpenQASM 2.0 program contains:

```text
include "qelib1.inc";
```

Cqlib handles `qelib1.inc` internally, and this file does not need to exist locally. Even if the include is omitted, Cqlib can recognize common qelib1 gate names; but for compatibility with OpenQASM 2.0 toolchains, the export still writes it out in a canonical way:

```text
include "qelib1.inc";
```

## 4. Exporting OpenQASM 2.0 from Cqlib

```python
from cqlib import Circuit
from cqlib.ir import qasm2

circuit = Circuit(2)
circuit.h(0)
circuit.cx(0, 1)

text = qasm2.dumps(circuit)
print(text)
```

Typical output:

```text
// This file is auto-generated by Cqlib v0.1.0.
OPENQASM 2.0;
include "qelib1.inc";

qreg q[2];

h q[0];
cx q[0],q[1];
```

The output is normalized, and the spaces, comments, register names or layout of the input file are not guaranteed to be preserved.

## 5. File reading and writing

```python
from cqlib.ir import qasm2

# first write the QASM text above to a file to be read
qasm2.dump(qasm2.loads(qasm_code), "input.qasm")

circuit = qasm2.load("input.qasm")
qasm2.dump(circuit, "output.qasm")
```

`load` is suitable for reading an external `.qasm` file; `dump` is suitable for saving a Cqlib circuit to a file for submission, archiving or passing to other tools.

## 6. Parameter expressions

Cqlib supports the parameter expressions commonly used in OpenQASM 2.0, for example:

```text
rx(pi) q[0];
ry(pi/2) q[0];
rz(3*pi/4) q[0];
```

Loading example:

```python
from cqlib.ir import qasm2

qasm_code = """
OPENQASM 2.0;
include "qelib1.inc";
qreg q[1];
rx(pi) q[0];
ry(pi/2) q[0];
rz(3*pi/4) q[0];
"""

circuit = qasm2.loads(qasm_code)
```

The current loader also accepts expression extensions common in some engineering projects, such as scientific notation without a decimal point, `1e-5`, and functions such as `asin`, `acos` and `atan`.

## 7. Measurement

OpenQASM 2.0 uses `creg` to represent a classical register, and the measurement syntax is:

```text
measure q[0] -> c[0];
```

Complete example:

```python
from cqlib.ir import qasm2

qasm_code = """
OPENQASM 2.0;
include "qelib1.inc";
qreg q[2];
creg c[2];
h q[0];
cx q[0],q[1];
measure q[0] -> c[0];
measure q[1] -> c[1];
"""

circuit = qasm2.loads(qasm_code)
```

On export, Cqlib maps internal measurement values to the `creg` form that OpenQASM 2.0 can represent. For a multi-bit measurement such as `measure_bits_into([0, 1], c)`, it is expanded into per-bit measurement:

```text
measure q[0] -> c0[0];
measure q[1] -> c0[1];
```

## 8. Custom gates

OpenQASM 2.0 supports `gate` definitions:

```text
OPENQASM 2.0;
include "qelib1.inc";
gate bell a,b {
    h a;
    cx a,b;
}
qreg q[2];
bell q[0],q[1];
```

On loading, Cqlib converts a custom gate into a `CircuitGate`. On export, if the `Circuit` contains a custom circuit gate that can be expanded into OpenQASM 2.0, the corresponding `gate` definition is generated as well.

## 9. Conditional execution

OpenQASM 2.0 supports limited classical conditions:

```text
if (c == 1) x q[0];
```

Cqlib supports this form of condition where the register as a whole equals an integer. Note that:

- OpenQASM 2.0 does not support `else`.
- OpenQASM 2.0 does not support general `while/for/switch`.
- When exporting to QASM2, Cqlib refuses complex control flow that cannot be expressed losslessly.

If the circuit contains complex dynamic semantics, OpenQASM 3.0 is preferred.

## 10. Support and limitations

| Capability | Loading | Export | Description |
|---|---|---|---|
| `qreg`, `creg` | Supported | Supported | Register names are normalized on export |
| qelib1 standard gates | Supported | Supported | `qelib1.inc` is handled internally |
| Parameterized gates | Supported | Supported | Common expressions are supported |
| Custom `gate` | Supported | Supported | Must be representable as an OpenQASM 2.0 gate body |
| `measure`, `reset`, `barrier` | Supported | Supported | Some complex combinations are normalized |
| `if (creg == int) qop` | Supported | Supported | The limited condition of OpenQASM 2.0 |
| `else/while/for/switch` | Not suitable | Lossless export not supported | OpenQASM 3.0 is recommended |
| General classical assignment | Not suitable | Not supported | Insufficient expressive power of OpenQASM 2.0 |

## 11. Troubleshooting common errors

| Symptom | Common cause | Handling |
|---|---|---|
| Parsing fails | A missing `OPENQASM 2.0;`, a syntax error or a gate parameter count mismatch | Confirm the format with a minimal example first, then add gates section by section |
| Export fails | The circuit contains control flow or instructions that OpenQASM 2.0 cannot represent | Switch to QASM3, or decompose/remove the complex semantics first |
| Gate names differ after another tool reads the file | Cqlib normalizes some gates, for example the `U1/U2/U3` mapping | Verify by matrix or circuit semantics, not only by the text gate names |
| Measurement register names change | The exporter generates canonical register names | This is normal behavior and does not affect measurement semantics |
