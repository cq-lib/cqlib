# Notebook and documentation integration

This page shows how to display a PNG generated by Cqlib in a Notebook and save the same figure into an asset directory that Markdown can reference.

---

## Task: display and save the same figure in a Notebook

```python
from pathlib import Path

from cqlib import Circuit
from cqlib.visualization import draw_figure

assets = Path("assets")
assets.mkdir(exist_ok=True)

circuit = Circuit(2)
circuit.h(0)
circuit.cx(0, 1)
circuit.measure(0)
circuit.measure(1)

draw_figure(circuit, output_path=str(assets / "bell.png"))
```

In a Notebook, the last line above displays the figure inline and saves the PNG to `assets/bell.png` at the same time. This approach suits experiment records, reports and paper supplementary material.

The generated result is as follows:

![Bell state circuit](assets/bell.png)

---

## Referencing in Markdown

After saving the PNG, reference it directly in Markdown:

```markdown
![Bell state circuit](assets/bell.png)
```

After referencing the image, the check points of this circuit diagram can be recorded below the figure:

```markdown
Figure 1 shows the Bell state preparation circuit: first apply an H gate to q0, then apply a CX gate with q0 as the control and q1 as the target.
```

A quantum circuit diagram usually needs to state the control qubits, target qubits, measurement positions and bit order clearly. Otherwise the figure only shows the circuit shape and cannot convey a verification conclusion.

---

## Organizing documentation asset directories

Keeping a separate asset directory for each group of experiments or each report prevents different figures from overwriting each other:

```text
docs/
  visualization/
    tutorial.md
    assets/
      bell.png
      ansatz_structure.png
      mapped_before.png
      mapped_after.png
```

File names should describe the task rather than use temporary names such as `figure1.png` or `test.png`.

## Regenerating figures automatically

When a group of experiments contains several figures, the generation logic can be consolidated in a single code block or script.

```python
from pathlib import Path

from cqlib import Circuit
from cqlib.visualization import draw_figure

assets = Path("assets")
assets.mkdir(exist_ok=True)

bell = Circuit(2)
bell.h(0)
bell.cx(0, 1)

draw_figure(bell, output_path=str(assets / "bell.png"))
draw_figure(bell, reverse_bits=True, output_path=str(assets / "bell_reverse_bits.png"))
```

The two generated figures can be referenced separately in Markdown:

![Bell state circuit](assets/bell.png)

![Bell state circuit with reversed bits](assets/bell_reverse_bits.png)

When the circuit construction code changes, rerunning this section updates the illustrations accordingly. If a generated figure does not match expectations, check the circuit construction and the visualization parameters first rather than editing the image content by hand.

## Saving visualization results

- For small circuits, both a text diagram and a PNG can be kept;
- For large circuits, save the key stages in preference to every intermediate circuit;
- Save the original PNG rather than keeping only a screenshot;
- Use specific task names for file names, such as `bell_reverse_bits.png` and `mapped_after.png`;
- When a figure involves bit order, measurement order or backend mapping, the corresponding convention must be written clearly in the experiment record.

---

## Common issues

When a figure is not displayed automatically in a Notebook, the returned SVG string can be displayed explicitly with IPython:

```python
from IPython.display import SVG, display
from cqlib.visualization import draw_figure

display(SVG(draw_figure(circuit)))
```

When a script only saves a file without displaying the figure, check whether `output_path` writes to the expected directory and confirm that the generated file can be opened by a local image viewer.

---

## Checks after updating figures

After modifying the circuit or the drawing code, the following order of checks can be used:

1. Rerun the code block or script that generates the PNG;
2. Confirm that the file names referenced in Markdown have not changed;
3. Open the generated PNG and check whether the control qubits, target qubits, measurement positions and bit order still match expectations;
4. If sampling results or state figures are included, confirm whether the data source is constructed results, local simulation or hardware results;
5. Check that file names contain no temporary names and that code blocks contain no absolute paths or local user directories.
